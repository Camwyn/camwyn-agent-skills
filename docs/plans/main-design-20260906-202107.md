## Problem Statement

We are building an autonomous, event-driven Obsidian synchronization system for AI coding agents across Antigravity, Cursor, and Claude Code. Instead of relying on detached post-commit scrapers or manual user slash commands, the agent autonomously maintains a live project memory in Obsidian by capturing commits in `Worklog.md`, architectural choices in `Decisions.md`, and pending tickets/tasks in `Tasks.md`—all dynamically linked back to `Overview.md`. The system operates under cross-platform constraints via universal agent behavioral rules, remains strictly non-invasive through granular opt-in flags in `obsidian-config.json` configured during `/obsidian-setup`, and safeguards against data loss using concurrency-safe `etag` editing.

---

## What Makes This Cool

- **Living Brain for Codebases**: As you write code and commit, Obsidian builds an effortless, structured log of *why* things happened, not just *what* lines changed.
- **In-Session Semantic Depth**: Unlike a dumb git post-commit hook that only sees commit messages, the AI in session understands the rationale, discarded alternatives, and unresolved blockers, logging true engineering memory in real time.
- **Zero Friction & Zero Extra Commands**: Developers don't need to remember to run `/obsidian-decision` or `/obsidian-commit`; the agent simply handles it as part of its core development loop.
- **Tripartite Organization with Bi-directional Linking**: Updates aren't dumped into a massive monolithic file. They are neatly partitioned into `Decisions.md`, `Worklog.md`, and `Tasks.md`, with `Overview.md` automatically creating and linking them.

---

## Constraints

- **Universal Cross-Platform & Cross-IDE Parity**: Must operate seamlessly on Windows, macOS, and Linux across Antigravity IDE, Cursor, Claude Code, and Gemini CLI without requiring OS-level shell hook daemons.
- **Agent-Driven Behavioral Rules**: Triggering must be governed by declarative agent rules in `.agents/rules/` and referenced in instructions, keeping the stack clean and portable.
- **Granular Opt-in Configuration**: Third-party users must be in complete control of which triggers are active via `~/.agents/obsidian-config.json` and during `/obsidian-setup`.
- **Safe Concurrent MCP Editing**: All writes must use the `obsidian_read_note` -> `etag` -> `obsidian_edit_note` loop to avoid overwriting edits made simultaneously in the Obsidian desktop app.

---

## Premises

1. **Rule-Based Triggering Over Platform Hooks**: Automated logging is guided by persistent agent behavioral rules (`.agents/rules/obsidian-live-sync.md`), avoiding brittle shell/git hook installations.
2. **Opt-in & Granular**: Configured via `obsidian-config.json` (`auto_sync: { enabled, on_commit, on_decision, on_todo }`) and prompted during `/obsidian-setup`.
3. **Tripartite Architecture**: Writes to `Decisions.md`, `Worklog.md`, and `Tasks.md`, and ensures they are dynamically linked in `Overview.md`.
4. **Concurrency Safety**: All writes enforce safe `etag` verification with automatic conflict retries.

## Approaches Considered

### Approach A: Rule-Directed Delegation (Minimal Viable)
- **Summary**: Install a single behavioral rule markdown file into `.agents/rules/` that instructs the agent to check `obsidian-config.json` after making any commit, ticket, or decision, and invoke the existing `obsidian-decision-sync` and raw MCP tool calls directly.
- **Effort**: S | **Risk**: Low
- **Pros**: Minimal diff; reuses existing skills.
- **Cons**: Lacks dedicated structured templates for `Worklog.md` and `Tasks.md`; requires more LLM cognitive load to format notes ad-hoc.
- **Reuses**: Existing `obsidian-decision-sync` logic, `install.ps1`, `obsidian-config.json`.

### Approach B: Unified Obsidian Lifecycle Manager & Rule Suite (Ideal Architecture)
- **Summary**: Add an `obsidian-auto-sync` skill that encapsulates the three handlers (`log_commit`, `log_task`, `log_decision`), updates `Overview.md` linking automatically, and pairs with a declarative behavioral rule file in `.agents/rules/obsidian-live-sync.md`. Update `/obsidian-setup` with an interactive onboarding step asking the user whether to enable auto-sync and which triggers to toggle.
- **Effort**: M | **Risk**: Low
- **Pros**:
  - Modular: Clear single source of truth for all three auto-sync operations (`Worklog.md`, `Tasks.md`, `Decisions.md`).
  - First-class setup wizard support: Users are prompted during `/obsidian-setup` with granular toggles stored in `obsidian-config.json`.
  - Self-healing linking: `Overview.md` automatically gains `[[Worklog]]` and `[[Tasks]]` links if missing.
  - Clean separation: Skills handle atomic Obsidian MCP transactions, while the Rule handles triggering criteria.
- **Cons**: Adds one new skill folder (`obsidian-auto-sync`) and updates `obsidian-setup` and `obsidian-project-init`.
- **Reuses**: `obsidian-decision-sync` ADR structure, `obsidian-project-init` note creation and linking logic, `obsidian-setup` wizard flow.

### Approach C: Hybrid Background Hook & Event Bus (Lateral)
- **Summary**: Install git hook scripts (`post-commit`) and an agent session hook that writes raw events to a staging file (`.agents/.sync-queue.json`), which a background daemon or session resume hook commits to Obsidian in bulk.
- **Effort**: L | **Risk**: Med-High
- **Pros**: Captures manual commits made outside the AI chat session.
- **Cons**: Violates agent-driven constraint; fragile on Windows with execution policies; lacks rich cognitive reasoning on *why* decisions were made.
- **Reuses**: Local file queues, git hooks.

---

## Recommended Approach

**Approach B (Unified Obsidian Lifecycle Manager & Rule Suite)** is chosen because it gives a cohesive, first-class experience: clean separation of concerns, automated `Overview.md` linking, granular wizard onboarding, and zero-dependency cross-platform execution across Antigravity, Cursor, and Claude Code.

## Success Criteria

1. **Config Schema**: `obsidian-config.json` supports:
   ```json
   "auto_sync": {
     "enabled": true,
     "on_commit": true,
     "on_decision": true,
     "on_todo": true
   }
   ```
2. **Setup Wizard Integration**: `/obsidian-setup` interactively prompts the user whether they want automated synchronization enabled and lets them configure triggers.
3. **Tripartite Note Management**:
   - Commits log to `Projects/<ProjectName>/Worklog.md`.
   - Tasks/TODOs log to `Projects/<ProjectName>/Tasks.md`.
   - Decisions log to `Projects/<ProjectName>/Decisions.md`.
4. **Overview Linking**: Whenever any of the above files are created or updated, `Projects/<ProjectName>/Overview.md` is updated to include links to them under `## Quick Links`.
5. **Agent Rule Deployment**: `install.ps1` and `install.sh` install the `.agents/rules/obsidian-live-sync.md` rule so the agent automatically executes the sync loop whenever a commit, decision, or ticket is created in session.
